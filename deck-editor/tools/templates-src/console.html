Why a rewrite

// the honest version

context

Three problems we could not patch

  • The sync path did every write twice; fixing it meant touching every caller.
  • Config lived in four places, and ENV won silently over the file.
  • Startup took 40 seconds on a laptop, which is where most debugging happens.
  • And one we found while rewriting: retries were unbounded on 503.
architecture

The new shape

gateway

Auth, rate limits, one entry point.

core

Single write path. Idempotent by key.

store

Append-only log, snapshots hourly.

workers

Everything async, bounded retries.

Every box is one process and one repo. The arrows are the only network calls.
Point at core: it is the only part that was rewritten from scratch.
core/write.ts

One write path

Every write goes through commit. The key makes a retry a no-op instead of a duplicate.

Callers never see the store. They see a promise and an id.

write.ts
export async function commit(key: string, patch: Patch) {    const seen = await log.has(key);    if (seen) return log.idFor(key);   // idempotent    const id = await log.append({ key, patch, at: now() });    queue.emit('written', id, { retries: 3 });    return id;}

migration

What a caller changes

services/orders.ts
async function place(order: Order) {    await db.insert('orders', order);    await db.insert('audit', { ref: order.id });    await sync.push(order);    const id = await commit(order.id, { order });    notify(order.customer);    return id;}

Three calls become one. The audit row and the sync are side effects of the log now, not the caller's job.

A codemod does this for 80% of call sites; the rest are listed in the migration issue.
