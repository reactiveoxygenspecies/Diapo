## Why Diapo

A plot made in Python can be interactive: the audience can zoom into it, read a value by hovering over a point, or
switch a series on and off. Most slide programs cannot hold such a plot, only a picture of it. An HTML deck can,
because a web page runs the same code that draws the plot. However, HTML decks are written in code, and building
one by hand is slow for anyone who did not set out to write web pages. Decks generated by an AI assistant spare the
writing but not the editing, since changing a word, nudging a figure or recolouring a title still means going back
to the code, or to the assistant, for what should take a click. That is, the HTML deck offered the figures but took
away the familiar way of working with slides.

Diapo was built to give that way of working back. It will feel familiar to anyone who has used PowerPoint: one
clicks, drags, resizes, rotates and retypes directly on the slide, while themes, fonts, colours, animations,
transitions, charts, tables, icons, equations (LaTeX) and chemical structures (SMILES) are set from a panel beside
it. The deck underneath, nevertheless, remains a web page with everything a web page can do. Interactive figures
drawn by the deck's own scripts, Plotly graphs for example, run once you trust the deck, and they are moved and
resized like any other element. Each deck is saved as one HTML file, with a folder beside it for its pictures, and
the file presents on its own in any modern browser, with a presenter view (speaker notes and a timer), an overview
of the slides, a laser pointer, drawing on the slide and step-by-step reveals.

Existing work comes along. PowerPoint (.pptx) and Markdown files can be imported, and a deck can be exported as a
PDF, as a handout with the speaker notes, as a single self-contained HTML file, or as an editable PowerPoint file.
Decks drafted by an AI assistant open like any other, provided they follow the [Diapo Format](diapo-format/README.md),
and the [`diapo-deck`](skills/diapo-deck) skill teaches Claude Code to write them, so that an assistant can draft
the deck and the last changes can be made by hand.

Nothing leaves the computer. Diapo runs locally, with no account, no sign-in and no telemetry, and it reaches the
network only when you look up a Google Font or show a video or web page from elsewhere on a slide. Your decks stay
in the folders you keep them in.

Diapo, in short, does not ask you to give up the way you already make slides. It gives that way of working the
reach of the web.

## Getting started

On Windows, the simplest route is the program itself. Download `diapo.exe` from the
[Releases](../../releases) page and double-click it; neither an installation nor Python is needed. Because the file
is not yet signed, Windows may warn the first time that it comes from an unknown publisher.

On any system, Diapo also runs from this repository, which requires Python 3.8 or newer and nothing else:

1. Download the repository (**Code > Download ZIP**, then unzip it), or clone it.
2. In the `deck-editor` folder, double-click `Start Diapo.bat` on Windows or `Start Diapo.command` on macOS (the
   first time, right-click > Open), or run `./start-diapo.sh` on Linux. From a terminal,
   `python3 deck-editor/serve.py [folder]` does the same (`py -3` on Windows).
3. Choose **Try the sample deck** for a tour, or **New** to start from a blank deck or from one of 31 designs.

Diapo looks for Chrome or Edge first, because either one gives it a window of its own and prints PDFs directly.
Without them, it opens in a tab of your default browser, Firefox included, and PDFs are saved through the browser's
print dialog; only the picker for fonts installed on the computer requires Chrome or Edge. Started from the
repository for the first time, Diapo opens the `workspace/` folder, whose decks stay on your computer and are never
committed to git.

## Development

The app has no build step and installs nothing when it runs. npm is needed only for the tests and for the tools
that copy the icon, maths and chemistry libraries into the app:

```
cd deck-editor
npm install              # Playwright, and the packages the build tools copy from
npm test                 # browser tests in Chrome
npm run test:firefox     # the same tests in Firefox (once before: npx playwright install firefox)
npm run test:py          # Python tests (Windows; elsewhere run the same unittest command with python3)
```

[Tests](deck-editor/README.md#tests), in the reference, describes the rest.
